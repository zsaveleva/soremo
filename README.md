# SOREMO CITY

Сервис моделирования сценариев реновации советских нежилых зданий Петербурга (MVP).

Пользователь выбирает здание на карте и получает отчёт: 2–4 сценария новой функции с ТЭП, зонированием и экономикой. После загрузки технического обследования точность отчёта растёт с ≈30 до ≈85%.

| Каталог | Что внутри |
|---|---|
| `api/` | Go: HTTP API, воркер очереди, миграции, сид, движок сценариев |
| `web/` | React + TypeScript: карта, отчёты, кабинет, админка |
| `seed/` | `buildings.geojson` (500 зданий из OSM), демо-отчёты, генератор `seed/osm` |
| `infra/` | конфиг S3-хранилища для docker compose |
| `docs/` | решения, ревью дизайна, скриншоты, отчёты Lighthouse |

## Запуск

Нужен Docker.

```sh
make up      # PostGIS, S3 (SeaweedFS), headless Chromium, API, фронтенд
make seed    # здания, контекст, демо-отчёты, пакеты, dev-пользователи
```

Откройте http://localhost:5173.

### Доступы в dev-режиме

Пароли создаёт `make seed` только при `APP_ENV=dev`.

| Роль | Email | Пароль | Что есть |
|---|---|---|---|
| Пользователь | `demo@soremo.local` | `demo1234` | email подтверждён, пакет на 25 объектов на 6 месяцев |
| Админ | `admin@soremo.local` | `admin1234` | модерация документов и заявок, пользователи, платежи (`/admin`) |

Без входа открыты карта, карточки объектов и три примера отчётов (ДК Кирова, «Скороход», ДК Газа).

При регистрации нового пользователя письмо в dev не отправляется. Ссылка подтверждения пишется в лог API и показывается на странице «Проверьте почту».

Оплата имитируется. Подходит любая карта с корректным номером, например `4242 4242 4242 4242`. Карта `4000 0000 0000 0002` показывает отказ банка.

### Разработка без Docker для API и фронтенда

```sh
docker compose up -d db
make seed-local
make dev-api      # :8080; миграции применяются при старте, PDF печатает локальный Google Chrome
make dev-web      # :5173; /api проксируется на :8080
```

## Демо на GitHub Pages

На каждый пуш в `main` workflow `.github/workflows/pages.yml` собирает статическую версию фронтенда и публикует её на https://zsaveleva.github.io/soremo/.

GitHub Pages отдаёт только статические файлы, поэтому в этой версии нет сервера:
- **Работает:** карта всех 500 зданий, фильтры, поиск и список, карточки объектов, три примера отчётов с PDF, конфигуратор пакетов, витрина `/design`. Данные готовит `web/scripts/build-static-data.mjs` из `seed/`; ответы API собираются в браузере (`web/src/api/static.ts`).
- **Недоступно:** регистрация, оплата, моделирование, документы, админка. На этих экранах показано пояснение.

PDF примеров лежат в `seed/demo_pdf/`. После правки демо-отчётов их нужно пересобрать на запущенном стеке:

```sh
for i in 1 2 3; do curl -o seed/demo_pdf/demo-$i.pdf localhost:5173/api/v1/demo/reports/$i/pdf; done
```

Локально статическая сборка: `cd web && VITE_BASE=/soremo/ npm run build:static && npx vite preview --base /soremo/`.

## Проверки

```sh
make test         # go test (интеграционные — на базе из docker compose) и tsc --noEmit
make lint         # go vet и golangci-lint
make e2e          # Playwright: гость, регистрация → пакет → отчёт → PDF, модерация (нужен запущенный стек)
make screens      # скриншоты всех экранов в docs/screens
```

Интеграционные тесты квот создают временную базу в PostGIS из compose. Если базы нет, они пропускаются. Другой сервер можно указать через `TEST_DATABASE_URL`.

## Переменные окружения API

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_ENV` | `dev` | `dev`: письма в лог, dev-пользователи в сиде, cookie без `Secure` |
| `HTTP_ADDR` | `:8080` | адрес API |
| `DATABASE_URL` | `postgres://soremo:soremo@localhost:5433/soremo?sslmode=disable` | PostGIS |
| `APP_URL` | `http://localhost:5173` | адрес фронтенда для ссылок в письмах |
| `CORS_ORIGIN` | `http://localhost:5173` | разрешённые источники через запятую |
| `JWT_SECRET` | dev-значение | подпись токенов; вне dev обязателен свой |
| `SMTP_ADDR`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | пусто | SMTP; пусто — письма пишутся в лог |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | пусто, `soremo` | S3-хранилище; без `S3_ENDPOINT` файлы лежат в `FILES_DIR` |
| `FILES_DIR` | `../.cache/files` | локальное хранилище документов и PDF |
| `CHROME_URL` | пусто | удалённый Chromium (`http://chrome:9222`); пусто — локальный Chrome |
| `PRINT_BASE_URL` | `APP_URL` | адрес фронтенда, который открывает Chromium для печати PDF |
| `SEED_DIR` | `../seed` | каталог сид-данных |

Фронтенд: `VITE_MAP_BASE=raster` переключает карту на растровые тайлы OSM, если векторные тайлы OpenFreeMap недоступны. Код компонентов при этом не меняется.

## Как заменить MockEngine

Движок — интерфейс `engine.ScenarioEngine` в `api/internal/engine/engine.go`:

```go
type ScenarioEngine interface {
    Run(ctx context.Context, in EngineInput) (EngineOutput, error)
    Version() string
}
```

1. Реализуйте интерфейс: вызов внешнего сервиса или библиотеки. Вход — снимок здания, контекст, метаданные принятых документов и уровень точности. Выход — резюме, сценарии, методика, предупреждения.
2. В `api/cmd/api/main.go` замените `engine.MockEngine{}` на свою реализацию — это одна строка, она помечена комментарием.
3. `Version()` сохраняется в каждом отчёте (`reports.engine_version`). Старые отчёты остаются читаемыми, новые помечаются новой версией.

Движок вызывается из воркера очереди (`jobs`), а не из HTTP-обработчика, поэтому долгий расчёт не блокирует API. Входной снимок хранится в `reports.input_snapshot`, и отчёт можно пересчитать на новом движке с теми же данными. Правила MockEngine описаны в `docs/decisions.md`.

## Как добавить город

1. Соберите `buildings.geojson` для города. Генератор `seed/osm` работает с любой территорией: поменяйте `area[...]` в запросах Overpass и центр в фильтре исторического центра, затем `make osm`.
2. Добавьте город в `api/cmd/seed/main.go` (`UpsertCity`: slug, название, bbox) и привяжите к нему здания.
3. API уже принимает `city=<slug>` в `/buildings` и `/buildings/search`. На фронтенде город задают границы карты в `web/src/features/map/BuildingMap.tsx` и `CITY_BBOX` в `useBuildings.ts`. Переключатель городов в MVP не показывается.

## Как поменять цены

Пакеты и цены — таблица `packages` в `api/cmd/seed/main.go` (переменная `packages`). Поменяйте суммы или сочетания и выполните `make seed`: пакеты обновятся без пересоздания базы. Конфигуратор на `/pricing` строится по ответу `/api/v1/packages`, поэтому сочетания, которых нет в таблице, отключаются автоматически. Цена в платеже всегда берётся из базы, а не от клиента.

## Данные

`seed/buildings.geojson` закоммичен, сборка от сети не зависит. Пересобрать его из OSM можно командой `make osm`: нужен доступ к Overpass, сырые ответы кешируются в `.cache/osm`. Демо-отчёты написаны вручную и лежат в `seed/demo_reports/*.json`; сид проверяет их на соответствие контракту движка.

Стиль карты: `web/scripts/build-map-style.mjs` перекрашивает Positron в палитру продукта и записывает результат в `web/public/map/style.json` (`npm run map-style`).
