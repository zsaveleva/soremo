# Развёртывание полной версии на VPS

Полная версия — тот же docker compose, что локально, за Caddy с HTTPS. Сертификат Let's Encrypt выпускается автоматически. Всё, что нужно для сервера, лежит в `deploy/`.

## Что сделать вам

### 1. Купить сервер

Подойдёт любой хостинг с оплатой картой РФ: Timeweb Cloud, Selectel, Yandex Cloud, REG.RU, Beget.

| Параметр | Значение |
|---|---|
| Система | Ubuntu 24.04 (или 22.04) |
| Процессор | 2 vCPU, архитектура **x86_64** (не ARM: образ PostGIS есть только для x86) |
| Память | 2 ГБ минимум, лучше 4 ГБ — Chromium для PDF и сборка фронтенда требуют памяти |
| Диск | от 30 ГБ |
| Стоимость | примерно 400–900 ₽ в месяц |

### 2. Добавить SSH-ключ при создании сервера

В панели хостинга найдите поле «SSH-ключ» и вставьте ключ с этого компьютера. Показать его можно командой:

```sh
cat ~/.ssh/id_ed25519.pub
```

Скопируйте всю строку, начиная с `ssh-ed25519`. Пароль от сервера хостинг пришлёт отдельно — его никому передавать не нужно.

### 3. Записать IP-адрес сервера

После создания сервера в панели появится его IP, например `203.0.113.10`. Проверьте, что вход работает:

```sh
ssh root@203.0.113.10
```

При первом подключении ответьте `yes`, потом выйдите командой `exit`.

### 4. Домен — по желанию

Без домена сайт будет доступен по адресу вида `https://203-0-113-10.sslip.io`. Это рабочий HTTPS-адрес, его можно сразу показывать.

Свой домен (например, `soremo.ru`) покупается у регистратора — REG.RU, Timeweb, Nic.ru. В DNS домена нужна **A-запись** на IP сервера. Запись начинает работать в течение нескольких минут или часов.

### 5. Почта — по желанию, можно позже

Пока почта не подключена, регистрация работает: ссылка подтверждения показывается прямо на странице «Проверьте почту». Чтобы письма уходили на почту, нужен SMTP-ящик. Подойдут Яндекс 360 или Mail.ru для бизнеса: заведите ящик `no-reply@ваш-домен` и создайте для него пароль приложения. Настройка — в разделе «Почта» ниже.

## Развёртывание

Если IP есть и `ssh root@<ip>` входит без пароля, развернуть может Claude Code с этого компьютера — достаточно написать ему IP (и домен, если он есть). Или сами, двумя командами из папки проекта.

```sh
# 1. Подготовить сервер: Docker, файрвол (открыты только 22, 80, 443), swap. Один раз.
ssh root@203.0.113.10 'bash -s' < deploy/bootstrap.sh

# 2. Выложить и запустить. Без домена:
ADMIN_EMAIL=you@example.ru deploy/deploy.sh root@203.0.113.10
#    или со своим доменом:
ADMIN_EMAIL=you@example.ru deploy/deploy.sh root@203.0.113.10 soremo.ru
```

Сборка на сервере занимает 5–10 минут. В конце скрипт выведет адрес сайта и пароли:

```
Готово: https://203-0-113-10.sslip.io
  Админ:  you@example.ru / <пароль>
  Демо:   demo@soremo.local / <пароль>
```

Пароли создаются случайными при первом запуске и хранятся на сервере в `/opt/soremo/deploy/.env`. Там же лежат пароль базы, секрет JWT и ключи хранилища. Этот файл не попадает в git и не перезаписывается при обновлениях.

## Обновление

После изменений в коде запустите ту же команду:

```sh
deploy/deploy.sh root@203.0.113.10 [домен]
```

Скрипт скопирует код, пересоберёт контейнеры и применит миграции. Данные, пароли и сертификаты сохраняются.

## Обслуживание

Все команды выполняются на сервере (`ssh root@<ip>`) в папке `/opt/soremo/deploy`.

| Задача | Команда |
|---|---|
| Состояние контейнеров | `docker compose -f compose.prod.yml ps` |
| Логи API | `docker compose -f compose.prod.yml logs -f api` |
| Перезапуск | `docker compose -f compose.prod.yml restart` |
| Пароли | `cat .env` |
| Список бэкапов | `docker compose -f compose.prod.yml exec backup ls -l /backups` |

### Бэкапы

Контейнер `backup` раз в сутки делает дамп базы и хранит 14 последних. Чтобы скопировать свежий дамп к себе:

```sh
ssh root@<ip> 'cd /opt/soremo/deploy && docker compose -f compose.prod.yml exec -T backup sh -c "cat \$(ls -1t /backups/*.dump | head -1)"' > soremo.dump
```

Восстановление на сервере (заменяет текущие данные):

```sh
docker compose -f compose.prod.yml exec -T db pg_restore -U soremo -d soremo --clean --if-exists < soremo.dump
```

Загруженные документы и PDF лежат в volume `soremo_s3data` и в дамп базы не входят.

### Почта

В `/opt/soremo/deploy/.env` заполните SMTP:

```
SMTP_ADDR=smtp.yandex.ru:587
SMTP_USER=no-reply@soremo.ru
SMTP_PASSWORD=<пароль приложения>
MAIL_FROM='SOREMO CITY <no-reply@soremo.ru>'
```

Затем выполните `docker compose -f compose.prod.yml up -d api`. После этого ссылка подтверждения перестанет показываться на странице и будет приходить письмом.

### Сменить пароли админа или демо-пользователя

Поменяйте `SEED_ADMIN_PASSWORD` или `SEED_DEMO_PASSWORD` в `.env` и выполните:

```sh
docker compose -f compose.prod.yml run --rm api seed
```

Если `SEED_DEMO_PASSWORD` пустой, сид демо-пользователя не создаёт. Уже созданный при этом останется — чтобы закрыть ему вход, задайте новый случайный пароль и снова запустите сид.

## Если что-то не работает

- **Сайт не открывается по HTTPS.** Caddy не смог получить сертификат: порты 80 и 443 закрыты в панели хостинга (у некоторых провайдеров есть отдельный сетевой файрвол) или A-запись домена ещё не обновилась. Смотрите `docker compose -f compose.prod.yml logs caddy`.
- **Сборка падает с нехваткой памяти.** Проверьте, что `bootstrap.sh` создал swap (`swapon --show`), или возьмите сервер с 4 ГБ.
- **PDF не скачивается.** `docker compose -f compose.prod.yml logs api chrome` — обычно Chromium не стартовал из-за нехватки памяти.
